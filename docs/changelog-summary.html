版本演進摘要

0.7 → 0.8 → 0.9：Hybrid LSP 擴張與工程強化

Hybrid LSP 的擴張主線

CBM 最有價值的演進是 Hybrid LSP 型別解析的語言覆蓋擴張：

版本新增/強化
v0.7.0新增 Python / PHP / C# Hybrid LSP；Go 與 C/C++ 強化（pre-built 跨檔 registry、generics）
v0.8.0新增 Java / Kotlin / Rust Hybrid LSP
v0.9.0語意邊（SEMANTICALLY_RELATED / SIMILAR_TO）、cross-repo 強化、semantic search 11-signal scoring

各版新增能力（摘要）

  • 語意搜尋：nomic-embed-code embeddings（768d int8）編譯進二進位——零 API key、本機向量搜尋，11-signal 組合計分（TF-IDF、RRI、API/Type/Decorator signatures、AST profiles、data flow、Halstead-lite、MinHash、module proximity、graph diffusion）。
  • Cross-repo：CROSS_* 邊、multi-galaxy 3D UI 佈局、cross-repo architecture summary。
  • Cross-service linking：HTTP route ↔ call-site 匹配 + confidence、gRPC/GraphQL/tRPC 偵測、channel（EMITS/LISTENS_ON）。
  • Team-Shared Graph Artifact：graph.db.zst（two-tier export、bootstrap 匯入、merge=ours）。
  • Session Coordination Daemon：exact-build admission barrier、activation transaction、owner-only logs。

為何這是「值得教學」的演進

看版本線可以學到：CBM 不是「從 0 突然 158 語系」——它是先有 tree-sitter 語法層，再一版一版把型別解析的語言覆蓋撐起來。v0.7（Python/PHP/C#）→ v0.8（Java/Kotlin/Rust）→ v0.9（語意邊 + 搜尋）是一條清楚的路線：語法 → 型別 → 語意。

看完這頁你應該能說出：CBM 的「語法 → 型別 → 語意」三階段演進、v0.7/v0.8 各新增哪些 Hybrid LSP 語言、v0.9 的語意搜尋與語意邊在哪。

教學解說

CBM 的版本演進有一條清晰的路線：語法 → 型別 → 語意。v0.7 新增 Python/PHP/C# 的 Hybrid LSP（型別解析）；v0.8 新增 Java/Kotlin/Rust；v0.9 則加入語意邊（SEMANTICALLY_RELATED / SIMILAR_TO）與語意搜尋。

理解這條路線有助於判斷你的專案能獲得多少 CBM 的解析能力——如果專案主要用 TypeScript，v0.6+ 就有完整的型別解析；如果是 Rust，需要 v0.8+。

Worked Example

根據專案語言選擇適合的 CBM 版本：

# 檢查你的專案用什麼語言
find src/ -name '*.py' | head -5    # Python → 需要 v0.7+
find src/ -name '*.rs' | head -5    # Rust → 需要 v0.8+
find src/ -name '*.ts' | head -5    # TypeScript → v0.6+ 即可

# 確認 CBM 版本支援
codebase-memory-mcp --version
# → 0.9.x（支援所有語言的 Hybrid LSP + 語意邊）

# 驗證型別解析是否啟動（看 trace_path 的結果品質）
codebase-memory-mcp cli trace_path --project my-project --function-name main --direction outbound

常見錯誤 / 診斷

症狀原因解法
Rust 函式的 CALLS 邊很稀疏使用 v0.7 或更早版本更新到 v0.8+ 以獲得 Rust Hybrid LSP
語意搜尋回傳不相關結果索引未完成或 embedding 未載入確認索引完成，檢查 nomic-embed-code 是否正確載入
CROSS_* 邊不存在未索引多個 repo 或未啟用 cross-repo索引多個 repo 到同一個 store
