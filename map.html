概念地圖

codebase-memory-mcp 知識圖譜的核心概念，一張圖看懂

CBM 做的事可以一句話講完：把你整個專案變成一張可查詢的知識圖譜，然後透過 MCP 用「問結構問題」取代「逐檔 grep」。下面從「輸入」到「輸出」拆解這張圖長什麼樣。

1. 輸入：你的 repo（加 IaC）

CBM 是結構分析後端，不內建 LLM——你的 MCP client（Claude Code / OpenCode 等）就是翻譯官。索引管線吃整個 repo：

程式碼158 種 tree-sitter 文法 · 本機解析 · 零 LLM 套件清單package.json · go.mod · Cargo.toml · pyproject.toml… IaC 檔案Dockerfile · K8s manifests · Kustomize overlays → Resource/Module 節點 Git 歷史git diff / githistory pass · change coupling

2. 索引流程：多 pass 管線

來源：架構總覽。tree-sitter 抽取定義與呼叫，再疊上 Hybrid LSP 型別解析（"Go to Definition" 等級）：

discover()檔案發現discover/ → structureAST 抽取 158 語系pass_calls / pass_definitions → semanticHybrid LSP 型別解析pass_lsp_cross / lsp_surface → routeHTTP 路由節點pass_route_nodes → cross跨服務/跨 repopass_cross_repo / pass_infrascan → store()SQLite 落盤store/
RAM-first：LZ4 壓縮讀入、in-memory SQLite、結束才單次 dump，記憶體用完即釋放

5. 查詢範例

// 誰呼叫了 ProcessOrder？
trace_path(function_name="ProcessOrder", direction="inbound")

// 結構搜尋
search_graph(name_pattern=".*Handler.*", label="Function")

// Cypher 死碼偵測
query_graph("MATCH (f:Function) WHERE NOT EXISTS { (f)<-[:CALLS]-() } RETURN f.name")

6. 社群偵測與語意

Louvain 社群依 CALLS 邊密度分群 → get_architecture 的 cluster Hybrid LSP輕量 C 型別解析，相容 tsserver/pyright/gopls/Roslyn 語意搜尋nomic-embed-code（768d int8）編譯進二進位 · 11-signal 計分 SIMILAR_TOMinHash + LSH 近複製偵測

7. 產出

graph.db.zst可 commit 的 zstd 壓縮圖快照（團隊共享，8–13:1） 3D UI--ui 變體 · localhost:9749 互動圖形界面
小結：index 一次、之後只做增量 → 圖存在 SQLite（WAL、ACID）→ 每次查詢比讀原始檔省 99.2% token。Daemon 會跨 session 共享 watcher/索引/UI，所有處理 100% 本機。
